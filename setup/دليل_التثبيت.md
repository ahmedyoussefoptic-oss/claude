# دليل تثبيت نظام علاقات العملاء (CRM) لمدرسة جديدة

هذه نسخة كاملة من النظام تعمل على **مشروع Firebase مستقل** خاص بالمدرسة (قاعدة بيانات، حسابات، ملفات، استضافة) — لا تتشارك أي بيانات مع أي مدرسة أخرى.

تشمل النسخة جميع الوحدات: الملاحظات والشكاوى، المشكلات التقنية، المفقودات، زيارات الفروع برمز QR ومواعيد الزيارة، الرحلات المدرسية، التقارير، الإشعارات، واتساب API (اختياري)، صلاحيات المستخدمين، و«المنصة» الخاصة بمنشئ النظام (الاستئذانات، العملاء الجدد، الطلاب الحاليون).

---

## 1) المتطلبات على جهاز التثبيت

| المطلوب | ملاحظة |
|---|---|
| **Node.js 24** أو أحدث | من nodejs.org |
| حساب Google | سيُنشأ به مشروع Firebase |
| بطاقة دفع لتفعيل خطة **Blaze** في Firebase | مطلوبة للدوال السحابية؛ التكلفة الفعلية لمدرسة واحدة عادة ضمن الحصة المجانية أو بضعة دولارات شهرياً |

---

## 2) إنشاء مشروع Firebase للمدرسة

1. ادخل إلى [console.firebase.google.com](https://console.firebase.google.com) ← **Add project** ← اكتب اسماً للمشروع (مثال: `alnoor-crm`). احفظ **Project ID**.
2. **ترقية الخطة:** ⚙️ Usage and billing ← **Blaze**.
3. **Authentication:** Build ← Authentication ← Get started ← فعّل **Email/Password**.
4. **Firestore:** Build ← Firestore Database ← Create database ← **Production mode** ← الموقع: **nam5 (United States)** (مستحسن، لأن الدوال تعمل في us-central1).
5. **Storage:** Build ← Storage ← Get started (الإعدادات الافتراضية).
6. **تطبيق الويب:** ⚙️ Project settings ← General ← Your apps ← أيقونة **</>** ← سجّل التطبيق ← انسخ قيم `firebaseConfig` (apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId).
7. **مفتاح الإشعارات (Web Push):** ⚙️ Project settings ← **Cloud Messaging** ← Web Push certificates ← **Generate key pair** ← انسخ المفتاح.

---

## 3) إعداد النسخة لبيانات المدرسة

1. فك ضغط الحزمة في مجلد على جهازك، وافتح الطرفية (Terminal) داخل المجلد.
2. ثبّت المكتبات:
   ```bash
   npm install
   cd functions && npm install && cd ..
   ```
3. انسخ ملف الإعدادات وعدّله:
   ```bash
   cp school.config.example.json school.config.json
   ```
   عدّل في `school.config.json`:

   | الحقل | المعنى |
   |---|---|
   | `school.nameAr` | الاسم الكامل بالعربي (يظهر في الرسائل والتقارير) — مثال: مدارس النور الأهلية |
   | `school.brandAr` | الاسم في رأس القائمة الجانبية — مثال: النور الأهلية |
   | `school.shortNameAr` | الاسم المختصر — مثال: النور |
   | `school.nameEn` / `brandEn` / `shortNameEn` | نفس الأسماء بالإنجليزي |
   | `school.lmsName` | اسم منصة التعلّم لدى المدرسة (يظهر في وصف المشكلات التقنية) |
   | `firebase.*` | القيم المنسوخة من الخطوتين 2-6 و 2-7 |
   | `appUrl` | رابط النظام — افتراضياً `https://<Project ID>.web.app` |
   | `ownerEmail` | بريد **منشئ النظام** (صاحب كل الصلاحيات) |
   | `whatsappApi` | `true` فقط إذا كان لدى المدرسة حساب واتساب API لدى تقنيات |
   | `logo` | مسار شعار المدرسة بصيغة **PNG** (مربع، 512×512 أو أكبر) |
   | `branches` / `departments` | الفروع والأقسام الأولية (تُعدّل لاحقاً من الإعدادات) |

4. ضع ملف الشعار بجانب `school.config.json`، ثم شغّل:
   ```bash
   node setup/configure.mjs school.config.json
   ```
   يقوم السكربت بكتابة إعدادات Firebase، واستبدال اسم المدرسة في كل الواجهات والرسائل، وضبط الفروع والأقسام والشعار وأيقونات التطبيق.

---

## 4) ربط النسخة بالمشروع ورفعها

```bash
npx firebase-tools login
npx firebase-tools use <Project ID>
```

**كلمات السر (Secrets)** — تُطلب مرة واحدة:

| السر | الغرض | طريقة الإعداد |
|---|---|---|
| `GMAIL_USER` | بريد Gmail لإرسال إشعارات البريد | `npx firebase-tools functions:secrets:set GMAIL_USER` |
| `GMAIL_APP_PASSWORD` | «كلمة مرور التطبيقات» لذلك البريد (من إعدادات أمان Google) | `npx firebase-tools functions:secrets:set GMAIL_APP_PASSWORD` |
| `TAQNYAT_WA_TOKEN` | فقط إذا `whatsappApi: true` — رمز Bearer من تقنيات | `npx firebase-tools functions:secrets:set TAQNYAT_WA_TOKEN` |

ثم البناء والرفع:
```bash
npm run build
npx firebase-tools deploy
```
> قد تظهر في النهاية رسالة عن «cleanup policy» — ليست خطأً، والرفع ناجح.
> إذا طُلب تفعيل خدمات Google (Cloud Functions, Cloud Build, Artifact Registry, Eventarc, Cloud Scheduler, Secret Manager) فوافق عليها؛ قد يحتاج أول رفع لإعادة المحاولة بعد دقائق حتى تكتمل صلاحيات الخدمات.

---

## 5) أول دخول (منشئ النظام)

1. Firebase Console ← Authentication ← Users ← **Add user**: أدخل `ownerEmail` نفسه وكلمة مرور.
2. افتح رابط النظام (`appUrl`) وسجّل الدخول بهذا الحساب — يصبح تلقائياً **«منشئ النظام»** بكامل الصلاحيات.

---

## 6) الإعداد داخل النظام

1. **الإعدادات:** راجع الفروع والأقسام والتصنيفات والتصنيفات الفرعية (ويمكن ترتيبها بالسحب)، وأرقام واتساب الفروع، ومهلة الحل (SLA) وساعات العمل، ومواعيد الزيارة.
2. **كلمة سر الإعدادات** (اختياري): من إعدادات منشئ النظام.
3. **سجل الطلاب:** الإعدادات ← استيراد ملف Excel للطلاب، بأعمدة بهذه الأسماء في الصف الأول: `id_num` (رقم الهوية)، `name`، `branch_name` (اسم الفرع كما في الإعدادات)، `stage_name` (القسم/المنهج)، `grade_name` (مثل Grade 5 أو KG 2)، `class_name`، `mobile` (جوال ولي الأمر)، و`gender` اختياري (M/F).
4. **المستخدمون:** أضف الموظفين وحدد لكل موظف فروعه وأقسامه والأقسام التي يطّلع عليها.
5. **رموز QR للفروع:** من صفحة «QR زيارات الفروع» واطبعها للاستقبال.
6. **واتساب API** (إن وُجد): الإعدادات ← واتساب API ← أسماء القوالب المعتمدة، وأضف رابط تقارير التوصيل الظاهر في «تشخيص الإرسال» داخل بوابة تقنيات (الوب هوك ← «أخرى» ← رابط الوب 1).

---

## 7) تحديث النسخة لاحقاً

عند استلام حزمة أحدث: فك ضغطها في مجلد جديد، انسخ إليه `school.config.json` والشعار، ثم كرر الخطوات 3 (تثبيت المكتبات وتشغيل configure) و 4 (build ثم deploy). البيانات محفوظة في قاعدة بيانات المدرسة ولا تتأثر بالتحديث.

> شغّل `configure.mjs` على نسخة جديدة غير مُعدّلة؛ لتغيير اسم المدرسة لاحقاً ابدأ من حزمة جديدة.

---

## ملاحظات أمان

- لا تشارك `school.config.json` أو أي كلمات سر خارج فريق التشغيل.
- كل مدرسة لها مشروع Firebase وقاعدة بيانات وحسابات مستقلة تماماً.
- قواعد الحماية (firestore.rules) تُرفع تلقائياً مع `deploy` وتمنع أي وصول غير مصرّح.
