# تصميم نظام شكاوى أولياء الأمور (الجيل الجديد - Firebase)

## 1. الهدف
إعادة بناء نظام شكاوى أولياء الأمور لمدارس المكتشف العالمية باستخدام أحدث تقنيات الويب (React) والاعتماد كلياً على بيئة Firebase كبنية تحتية (Backend-as-a-Service)، للتخلص من الاعتماد على الخوادم التقليدية (PHP/MySQL) وتقديم تجربة مستخدم (UX/UI) استثنائية وسريعة.

## 2. الهيكلة التقنية (Architecture)

### 2.1. واجهة المستخدم (Frontend)
- **الإطار:** React + Vite.
- **التصميم:** سيتم تبني تصميم "Premium" عصري يعتمد على Glassmorphism، مساحات بيضاء واسعة، وخطوط عصرية (مثل Google Fonts: Cairo أو Tajawal لدعم العربية بشكل ممتاز)، مع تأثيرات حركية (Micro-animations) باستخدام Framer Motion لجعل الواجهة تنبض بالحياة.
- **إدارة الحالة:** Zustand لإدارة حالة المستخدم والتنبيهات.
- **التوجيه:** React Router.

### 2.2. البنية التحتية (Firebase)
- **قاعدة البيانات (Firestore):** قاعدة بيانات NoSQL فورية التحديث (Realtime).
- **المصادقة (Firebase Auth):** الدخول بالبريد الإلكتروني وكلمة المرور. سيتم استخدام Custom Claims لتحديد صلاحيات المستخدمين (Admin, Manager, CS, Spec) لضمان الأمان في قواعد البيانات.
- **الملفات (Firebase Storage):** رفع المرفقات (صور، PDF، صوتيات) بشكل آمن.
- **الاستضافة (Firebase Hosting):** لاستضافة تطبيق React وتقديم أداء سريع جداً.
- **المهام الخلفية (Cloud Functions):** دوال Node.js تعمل في الخلفية للتعامل مع:
  - محرك التذكيرات والتصعيد (SLA Engine) الذي يعمل كل ساعة (مجدول).
  - تسجيل حركات التدقيق (Audit Logs) بشكل آمن لا يمكن تزويره من العميل.

## 3. تصميم قاعدة البيانات (Firestore Collections)

- **`users`**: بيانات الموظفين، فروعهم، وأدوارهم.
- **`branches`**: الفروع المتوفرة.
- **`complaints`**: المستند الرئيسي للشكاوى. يحتوي على مصفوفة `history` للحركات، ومصفوفة `attachments` للمرفقات.
- **`kb`**: قاعدة المعرفة لحلول الشكاوى المتكررة.
- **`settings`**: إعدادات النظام (SLA، رسائل الواتساب، إلخ).
- **`notifications`**: إشعارات المستخدمين داخل النظام.
- **`audit`**: سجل العمليات على مستوى النظام.

## 4. القيود والمواصفات العامة (Global Constraints)
- **لغة الواجهة:** العربية (RTL) بشكل أساسي.
- **الأمان:** يجب تطبيق Firestore Security Rules بحيث لا يرى الموظف إلا شكاوى فرعه (باستثناء الإدارة العامة)، ولا يستطيع التعديل إلا حسب دوره.
- **استقلالية المهام:** يجب بناء التطبيق كمكونات مستقلة (Components).

## 5. واجهات النظام الرئيسية
1. **لوحة المؤشرات (Dashboard):** عرض الرسوم البيانية وإحصائيات الأداء في الوقت الفعلي (باستخدام Recharts).
2. **شاشة تسجيل الشكوى:** نموذج سريع مع دعم السحب والإفلات للمرفقات وتسجيل الصوت.
3. **قائمة الشكاوى ومساحة العمل:** عرض الشكاوى كقائمة مع فلاتر سريعة، وفتح تفاصيل الشكوى في Modal جانبي أو صفحة تفصيلية لسهولة الوصول.
4. **بوابة التتبع لولي الأمر:** صفحة عامة (لا تتطلب تسجيل دخول) بتصميم نظيف وسهل الاستخدام على الجوال.
